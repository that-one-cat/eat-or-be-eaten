# scripts/ui - HUD, menus, mutation-tree screens

UI reads sim state through signals/queries and sends player intent as commands. It never mutates sim state directly. Controller-friendly layouts, readable at 1280x800 (Steam Deck), all strings through `tr()` once localisation is introduced.

## Screens and flow (S6)
- `main.tscn` (`scripts/main.gd`) is the flow: main menu -> Play (fade, threaded load of `run_scene` = `reef.tscn` into `Run`) -> Esc pause (tree paused; the run is Pausable, the screens Always) -> victory on the `VICTORY` event -> menu. `reef.tscn` stays runnable on its own (no menu) for captures and benches. Capture-only arg `-- --s6-screen=main_menu|victory`.
- Screens are scenes in `game/scenes/ui/` (root CanvasLayer + `Root` Control carrying `res://ui/theme/main_theme.tres`): `main_menu.tscn` (`MainMenu`), `pause_menu.tscn` (`PauseMenu`), `settings_menu.tscn` (`SettingsMenu`), `victory_screen.tscn` (`VictoryScreen`), `tutorial_hints.tscn` (`TutorialHints`: 4 event-driven hints in the first minute, hidden during a pick and while paused). Screens emit requests; `main.gd` owns the state.
- `game_settings.gd` (`GameSettings`): `user://settings.cfg` (`[input]` sensitivity / invert_y / control_mode (T1.4, a mode id of `data/controls/modes.json`, unknown = `classic`; `SettingsMenu` has a selector with the description under it), `[audio]` master / music / sfx volume 0..1, `[graphics]` quality_tier: `"auto"` until the user picks Low/High, so detection runs at every start), injectable path for tests, `apply_audio()` (buses `Master`, `Music`, `SFX` from `game/default_bus_layout.tres`), `apply_input(PlayerInput)`. Quality applies on the next run. `SettingsMenu` also saves on a window close request while it is open.
- The death toast is the HUD's (`hud.gd` `show_death_toast`, theme variation `HudToast`).
- Scripted path test: `tests/scenarios/ui_flow.tscn` (a `tools/check.sh` step).

## In-game HUD and overlays (S6)
- `Hud` (`hud.gd`, node `Hud` in `reef.tscn` / `reef_greybox.tscn`, replaces the S3 `TempHud`): band badge + growth / health / hunger (top-left), boost bar + 3 ability slots with lock, cooldown sweep (`SimWorld.ability_cooldown_left`), ready pop and InputMap key hints (bottom-left), run timer + deaths (top-right), boss HP bar + trailing chip bar while `boss_engaged()` (top-centre), presence markers, centre banners / death toast / flash / edge vignette (API for FeedbackFx and BossFx: `show_band`, `show_banner`, `show_death_toast`, `flash`, `vignette`, `set_overlay_open`). Theme: `res://ui/theme/main_theme.tres` (type variations `HudPanel`, `BandBadge`, `HudSmall/Value/Title/Banner/Toast`, `GrowthBar`, `HealthBar`, `HungerBar`, `BoostBar`, `BossBar`, `BossChipBar`, `CardButton`, `Card*`, `Overlay*`; colours in the `Palette` type).
- `MutationPickOverlay` (`mutation_pick_overlay.gd`, CanvasLayer 5): polls the player's `pending_offer`; one card per offered node (branch + tier, icon placeholder, name, `description`, key hint), click or `pick_mutation_1..3` (keys 1-3) submit `PICK_MUTATION`; picks are ignored for 0.6 s after opening (held bite clicks). Signals `opened` / `closed`. Only set up when `PlayerInput` drives the fish.
- `PresenceIndicators` (`presence_indicators.gd`): pure `visible_markers(player, basis, camera, creatures, sector_deg, min_len_ratio, radius_m)` (tests: `test_s6_presence.gd`) + the neutral edge chevrons (same look for every creature, opacity by distance only).
- `PlayerInput`: `bite_dash` (right mouse) / `sonar` (Q) submit `ABILITY`; while an offer is open no gameplay input is sent and the mouse is free (recaptured when the offer is gone). Bite (F1): a press submits `BITE(-1)`, holding `bite` re-submits it once per sim tick; hold-repeat is armed only after a frame with the button released while captured (the capture click, a pick-card click or a pause-menu click never becomes a held bite).
- Project display stretch is `canvas_items` / `expand` (base 1280x720): the UI scales crisply to 1080p and HiDPI windows.

## Target health bars (feat-target-health-bar)
- `TargetHealthBars` (`target_health_bars.gd`, a Node3D added in code by `reef_greybox.gd`, so both maps have it): the player's bite on a living NPC (BITTEN with `other_id` = the player) puts a slim world-space HP bar above it; no bar on the player, the boss (HUD boss bar) or NPC-vs-NPC fights. Pool of `TargetBarTracker.CAP` (8) `MeshInstance3D` quads with one shared `fx_target_bar.gdshader` material, created at setup and hidden when unused; no viewports, no text.
- `TargetBarTracker` (`target_bar_tracker.gd`, node-free; tests `tests/test_target_health_bars.gd`): which targets have a bar. Constants: `CAP` 8 (a new target when full replaces the one hit longest ago), `HOLD_S` 4.0 (fully visible after the player's last hit), `FADE_S` 0.5 (then fades out). Time is sim ticks, so a paused world freezes the fade. A bar goes at once when the target is removed (died, eaten, demoted) or out of range.
- Look constants in `target_health_bars.gd`: width = visual length (`SimWorld.effective_length`, so an inflated puffer counts) x `WIDTH_PER_LENGTH` 0.8, clamped to 0.07-0.2 x the camera distance (`WIDTH_MIN_FRAC` / `WIDTH_MAX_FRAC`: same screen size range at every band); height = width x 0.14, at least 0.012 x the camera distance; centre lifted 0.4 x length + half the height + 0.015 x the camera distance above the body; range = band camera distance x 15, clamped to 8-60 m (`FeedbackFx.FX_RANGE_M`).

## God menu and console (T1.1, dev builds only)
- Decision: `docs/decisions/2026-11-05-god-menu-dev-builds-only.md`. The tools exist only when `GodBuild.allowed()` (`OS.is_debug_build()` or the export feature `god_menu`); a release export creates nothing. `Main._ready` loads `god_host.gd` by path behind that gate (`_god`), and calls `run_started(loop, run)` (in `start_run` after RUNNING), `run_ended()` (`_free_run`) and `consumes_pause()` (Esc in `_input`).
- `god_build.gd` (`GodBuild.allowed(is_debug, feature)`), `typed_words.gd` (`TypedWords`: `load_file()` / `validate_words()` for `data/god/typed_words.json`, inner `KeySet`; schema in `data/README.md`), `typed_word_matcher.gd` (`TypedWordMatcher`: node-free, two buffers (typed characters and physical key letters), suffix match, 1.5 s timeout, ignores echo / releases / ctrl-alt-meta combos).
- `god_host.gd` (`GodHost`, child of Main, ALWAYS): owns the matcher, the registry, the context, the menu and the console. Listens in `_unhandled_input` (a focused LineEdit / TextEdit starves it, plus an explicit focus check; letter keys are never consumed). Typing the dev word while a run exists unlocks the session (in memory only) and opens the menu; then the menu keys toggle the menu and the console keys open the console. The menu does not pause the tree and releases the mouse; the console pauses the tree and restores the previous paused state on close (it recaptures the mouse only if the run was running, no menu is open and no mutation pick waits). A run end hides both without touching pause or mouse.
- `god_menu.gd` (`GodMenu`, CanvasLayer 30): `register_panel(id, title, builder: Callable(ctx: GodContext) -> Control)` adds or replaces a tab (built lazily on open, rebuilt after `set_context`); stubs `tuning` (T1.3), `gallery` (T5.3) and `commands` (listed from the registry). `open() / close() / toggle() / is_open()`, signals `opened`, `closed`, `console_requested`.
- `god_console.gd` (`GodConsole`, CanvasLayer 31): log + command line with history (Up / Down), `submit(line)`, `print_line`, `clear`, `open() / close() / toggle()`, signals `opened`, `closed`. Esc and the console keys close it (read in `_input` while open).
- `god_commands.gd` (`GodCommands`, node-free registry): `register(name, help, handler: Callable(args: PackedStringArray, ctx: GodContext) -> String, usage)` (a repeated name replaces the older command), `execute(line, ctx)`, `names()`, `help_text(cmd)`; built-ins `help [cmd]`, `clear`, `menu`, `close`. `god_context.gd` (`GodContext`): `world`, `player_id`, `loop`, `player_input`, `camera`, `run`, `main`, `player()`, `log(text)`; signals `logged`, `clear_requested`, `menu_requested`, `close_requested`.
- T1.2 commands: `god_sim_commands.gd` (`GodSimCommands.register_all(cmds)`, called by `GodHost.setup`): `tp <place|x y z>` / `tp list` / `places`, `band <1-4>`, `xp <n>`, `heal`, `spawn [species [len]]` (no argument lists the spawnable species), `food [n]` (glowing bits; baked food sites cannot be added at runtime), `despawn`, `god` / `hunger` / `noclip [on|off]` (no argument toggles), `speed <x>` (0.05..8, via `world.debug.time_scale`, never `Engine.time_scale`), `event [list|trigger <id>]` (scheduler stub "no event scheduler yet (T6.1)"; `list` counts the events of the last 90 ticks), `overlay <name> [on|off]` / `overlay list` (obstacles, zones, grid, detect, bitecue), `boss [tp|hp <n>|stun|heal|win]`. Every handler validates its arguments, calls only `SimDebug`, and answers in text; after `band` / `xp` it says "a mutation pick is pending" while the world waits for a pick. The console pauses the game, so band / xp / boss HP show up when it closes (or use the F1 menu buttons, which do not pause).
- Commands tab of the F1 menu: `GodCommands.register_quick(provider: Callable(ctx) -> PackedStringArray)` lets a command set add ready-made lines (`GodSimCommands.quick_lines`: one `tp` per map place, `band 1..4`, speed presets, one `spawn` per species, overlays, boss shortcuts ...); the tab shows one button per line, the answer under the console button and in the console log.
- `god_aim.gd` (`GodAim`, static, read-only): `aim_point(world, player, dir)` = the "crosshair" for `spawn` / `food` (the game has none): terrain-clipped march along `PlayerInput.aim_direction()` (the player's heading without a PlayerInput), reach `clamp(12 x length_m, 3, 40)` m in 40 steps, stops at the seabed, an obstacle (0.6 m clearance), the surface or the map box and returns the last free point. `GodContext.aim_point()` / `GodContext.overlays()` (lazy `DevOverlays` under the map root) are the helpers commands use.
- `--god-script=<file>` (`god_script.gd`, `GodScript`; honoured only when `GodBuild.allowed()`, via `GodBuild.script_arg`): `Main._ready` starts a run by itself (`_run_god_script`, like `_capture_victory`) and `GodHost.run_script(path)` executes the file once. One step per line, `#` comments, `wait <s>`, `wait_ticks <n>`, `shot <name>` (user://god_shots/<name>.png, skipped headless), `quit`, anything else = a console command; the file is parsed first and a malformed line aborts it with `line N: ...`. Example: `wait_ticks 30` / `tp cave` / `band 3` / `spawn shark` / `shot cave_shark` / `quit`.
- T1.2 / T1.3 / T5.3 only register commands and panels (`host.commands.register(...)`, `host.menu.register_panel(...)`); UI code never writes sim state (it calls documented `SimDebug` functions).
