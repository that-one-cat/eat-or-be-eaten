# scripts/sim - pure simulation

Rules that live here (hard design rules, see root `CLAUDE.md`):

- No rendering nodes, no `SceneTree` dependency: classes extend `RefCounted` (or `Resource` for data), so they run headless and later on a dedicated server.
- Server-authoritative-ready: the sim owns world state (positions, sizes, hunger, growth, eat results). Presentation reads state and never mutates it.
- Input arrives as **commands** (a small data object per player per tick), never as direct calls into state.
- Deterministic by seed: NPC schools are generated from a seed plus events ("fish #k eaten"); never one network object per NPC fish.
- Size bands, eat rules, growth, abilities and mutations are **data-driven**: tables in `res://data/`, loaded here, no hard-coded species logic.
- Same uniform spatial grid for eat checks, flocking and (later) network interest management.

Contents (each class documents its rules in its `##` header):

- `sim_world.gd` (`SimWorld`) - world state, fixed 30 Hz `step()` with named phases (`PHASE_NAMES`; per-phase timing in `phase_usec` / `last_step_usec` only when a bench injects `profile_clock`, the sim never reads a clock), `state_hash()`, event log.
  - Aim assist (T1.5): `_assisted_bite_target` is the soft lock for player bites without a target; with `aim_assist_strength` <= 0 (shipped) `_bite_target` runs the strict-cone path unchanged. Keys, score formula and lock memory: `docs/data/rules.md`.
  - Bite cue query (T1.11, God tools only): `peek_bite_target(player_id) -> int` runs the same `_bite_target` selection (assist included) with `commit = false`, so the aim lock memory is read but never written; read-only, ignores the cooldown / request buffer and food sites, no sim phase calls it.
  - Bite lunge (T1.6): `_start_bite_lunge` / `_bite_lunge_carry` add a short forward carry to the position step of a player after a landed bite; with `lunge_strength` <= 0 (shipped) nothing runs. Keys, model and cap: `docs/data/rules.md`; per-band distance `lunge_distance_m`: `docs/data/size_bands.md`.
  - Control modes (T1.4): `SET_CONTROL_MODE` sets `SimEntity.control_mode` of a player; `_player_aim` / `_player_lunge` give the effective strengths `max(rules value, mode value)` (modes: `data/controls/modes.json`, `ContentDB.get_control_mode`); the mode id is hashed only while not `classic`. Schema and input side: `docs/data/controls.md`.
- `sim_command.gd`, `sim_command_queue.gd` - the only input path; `sim_event.gd` - what views read; `sim_entity.gd` - per-creature state; `sim_rng.gd` - the only RNG.
- `sim_rules.gd` - pure eat/bite/growth formulas; `content_db.gd` - JSON loading + validation of everything in `res://data`.
- `spatial_grid.gd` - the one uniform grid (rule 7); `seabed_field.gd` - analytic seabed + obstacles (sphere, capsule, box, rounded oriented box `obb`; map obstacles + the baked dressing proxies of `ContentDB.get_proxies`) with a broad phase and per-cell narrow-phase lists.
- `npc_brain.gd` - temperament state machines (commands only); `npc_spawner.gd` - per-zone spawners for the non-schooling species and the population on/off switch. Fish packs (map `spawners[].group`): the spawner owns pack membership (fixed per slot, hashed in `write_state`; read API `pack_leader`, `pack_radius_m`, `pack_index`, `pack_count`, `pack_members`), the brain only follows the leader while wandering; a pack is never a shared entity.
- S4 population (rule 3/4): `school_system.gd` (`SchoolSystem`) - seeded schools, centre and member offsets are pure functions of (seed, tick), state changes only through `SimEvent`s (`apply_event` replays them); `tier_manager.gd` (`TierManager`) - promotion/demotion of school members near players with hysteresis and caps; `plankton_field.gd` (`PlanktonField`) - plankton as a lazily regrowing density grid (optional seeded patchiness: per-column cap `cell_cap`); the krill clouds are its subclass `krill_field.gd` (`KrillField.from_block`, one per map `krill` entry, grid clipped to its zones): individual krill per cell (static hashed layout + a closed-form drift the shader mirrors), alive bits per touched cell, one krill eaten (nearest to the mouth) per `PLANKTON_EATEN`, regrowth one krill at a time.

Read API for presentation and benches: `SimWorld.schools` (`school_count`, `get_school`, `center_at`, `heading_at`, `velocity_at`, `member_offset`, `member_position`, `member_slot`, `member_wobble`, `School.alive` / `promoted`), `SimWorld.plankton` (`density_at`, `cell_cap`, `cell_at`, `cell_center`, `touched_cells`, `bounds`), `SimWorld.krill` (`Array[KrillField]`, same API + `critter_count`, `alive_mask`, `critter_layout`, `critter_position`, motion numbers), `SimWorld.npc_count(tier)`, events `SCHOOL_MEMBER_*` / `PLANKTON_EATEN` (`data.field`: 0 plankton, i + 1 = `krill[i]`).
- S6 run: `progression.gd` (`Progression`) - seeded mutation offers on band-up, picks, passives; `abilities.gd` (`Abilities`) - Bite-Dash lunge + bite, Sonar pulse, cooldowns; `boss_brain.gd` (`BossBrain`) - giant shark state machine (PATROL/ENGAGE/TELL/DASH/DISENGAGE/STUNNED); the boss rules (charge hits, stun, finisher, giant remains, VICTORY) are SimWorld's `boss` phase. `sim_debug.gd` (`SimDebug`) - test/debug hooks only (`force_band_up`, `set_xp`, `set_boss_hp`, `force_victory`), never called by normal play. God tools (T1.2, only through `GodHost`, debug / test builds): `SimDebug.State` (`god`, `hunger_lock`, `noclip`, `time_scale`, `spawned_ids`) lives in `SimWorld.debug` (null = normal rules, created by `SimDebug.state(world)`; the object itself is **not hashed**, listed in the "Not hashed on purpose" doc of `state_hash`, but its effects are: god / hunger lock / heal change entity `hp`, `max_hp` and `hunger`, which `state_hash` does cover, while rng and positions stay identical; `debug == null` and an empty `SimDebug.State` hash identically); functions `teleport` (through `_constrain`, stops the entity, grid sync), `set_band` (XP of the band threshold; band N offers only band N's mutation), `heal`, `set_god`, `set_hunger_lock`, `set_noclip`, `set_time_scale` (clamp 0.05..8), `spawn_refusal` / `spawn_species` (interactive and large tiers only, a second boss is refused while `boss_id() >= 0`), `spawn_food_bits` (glowing bits, XP not scaled by the eater's size; baked food SITES cannot be added at runtime), `despawn_debug`, `boss_stun`, `boss_heal`. Hook points in `sim_world.gd` (each a single `if debug != null ...` guard, all no-ops while `debug == null`): field `debug` after `vitals_enabled`; `step()` right before `_resolve_deaths()` -> `SimDebug.apply_overrides` (god: HP refilled, hunger lock: hunger refilled; this tick's lethal damage is undone before `_die`, starvation of the vitals phase on the next tick, so hunger reads one tick of drain below the maximum at the end of a step); top of `_constrain` and of `_substep` -> noclip for players (map box and surface still hold; `SimDebug.noclip_constrain`). `time_scale` is read by `GameLoop._process` only (the sim does not know it). A god-mode player swallowed by a bigger fish still gets the `EATEN` event of that tick, but never `DIED`.

Read API (S6): `SimWorld.paused_for_pick`, `pick_pause_enabled` (switch), `run_won`, `run_ticks`, `boss_id()`, `boss_engaged()`, `boss_defeated_tick()`, `ability_cooldown_left(entity_id, ability_id)`, `players()`; `SimEntity.mutations`, `abilities`, `pending_offer`, `picks_offered_for_band`, the passive fields (`presence_sector_deg` for presence markers), `dash_until_tick`, `boss_state` (`BossBrain.State`) / `boss_dir`; commands `SimCommand.pick_mutation()`, `SimCommand.ability()`; events `MUTATION_*`, `ABILITY_USED`, `DASH_*`, `SONAR_PULSE`, `BOSS_*`, `VICTORY` (data keys in `sim_event.gd`).
- Food task: `food_sites.gd` (`FoodSites`) - baked food sites (eggs, snails, edible decor) with sparse state: `site_count`, `site_type`, `site_pos`, `site_radius`, `site_alive`, `site_hp`, `site_max_hp`, `site_soft`, `sites_near_into` (live sites, ascending id), `write_state`; `SimWorld.food` (null without `maps/<id>_food.json`), events `SITE_BITTEN` / `SITE_EATEN` / `SITE_RESPAWNED`; test entry `FoodSites.from_records(content, records, cell_m)`.
